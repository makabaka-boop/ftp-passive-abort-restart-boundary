# readonly-ftpd

单进程、零依赖的只读 FTP 演示服务(Node.js ≥ 18)。重点演示:**数据连接被堵住时,控制连接上的 ABOR 依然生效**,以及每次传输的终态严格隔离——旧传输的 accept / drain / 结束回调绝不会替新传输发出应答。

## 快速开始

```bash
docker compose up --build
```

或不用 Docker:

```bash
node ftpd.js            # 控制端口 2121,EPSV 数据端口默认临时分配
```

- 控制端口:`2121`;EPSV 数据端口段:`30000-30009`(Compose 已映射)
- 固定演示账户:`demo` / `demo123`
- 内置三份二进制演示文件(确定性生成,最多 32 KiB):

| 文件        | 大小     |
| ----------- | -------- |
| `alpha.bin` | 32768 B  |
| `beta.bin`  | 8192 B   |
| `gamma.bin` | 64 B     |

试用(curl 默认使用 EPSV):

```bash
curl ftp://demo:demo123@127.0.0.1:2121/alpha.bin -o alpha.bin
curl -r 100-199 ftp://demo:demo123@127.0.0.1:2121/beta.bin   # REST 断点续传
```

## 协议支持

仅支持:`USER`、`PASS`、`TYPE I`、`EPSV`、`REST`、`RETR`、`ABOR`、`NOOP`、`QUIT`。
上传(`STOR`/`APPE`/…)、主动模式(`PORT`/`EPRT`)、`PASV` 与目录操作(`LIST`/`CWD`/`MKD`/…)一律 `502`;未识别命令 `500`。

### 关键语义

- 控制命令按 CRLF 增量读取;数据发送与控制读取独立推进,数据连接堵住不阻塞控制命令处理。
- 每次 `EPSV` 替换旧监听器(旧监听器关闭、其上滞留连接被销毁;迟到的旧监听器连接被拒绝)。
- 每次 `RETR` 独占自己的监听器、数据 socket、文件游标与终态;`REST` 偏移只被下一次**被接受的** `RETR` 消费(被 `550`/`425` 等拒绝的 `RETR` 不消费)。
- 活动传输期间,除 `ABOR`/`NOOP`/`QUIT` 外的命令一律 `450` 拒绝。
- 数据连接超时(`FTPD_ACCEPT_TIMEOUT_MS`,默认 10 s)→ `425`;传输中途失败 → `426`。
- 活动中止:先关闭数据侧,再按序 `426`、`226`;传输已完成或没有活动传输时 `ABOR` → `225`。
- 成功与中止竞争只允许一种结论:终态经 `settle()` 一次性生效,旧传输上的迟到回调被代次检查丢弃。
- 因此客户端仅凭控制连接上的应答序列即可判定每次传输的结局(`150` 之后的第一个 `226`/`426`/`425` 即该次 `RETR` 的结论)。

## 环境变量

| 变量                     | 默认     | 说明                                   |
| ------------------------ | -------- | -------------------------------------- |
| `FTPD_PORT`              | `2121`   | 控制端口(`0` = 临时端口)             |
| `FTPD_ACCEPT_TIMEOUT_MS` | `10000`  | 等待数据连接的超时(超时回 `425`)     |
| `PASV_PORT_MIN` / `MAX`  | `0` / `0`| EPSV 监听端口段;`0` = 临时端口       |
| `FTPD_HOOK_PORT`         | 关闭     | 测试钩子端口(见下,仅测试用)        |

## 测试钩子(可控发送屏障)

设置 `FTPD_HOOK_PORT` 后开启一个行协议端口,用于测试确定性复现竞争:

```
PING            -> PONG
BARRIER <n>     -> OK barrier at n     # 传输在已发送 n 字节后暂停(每传输一次)
BARRIER OFF     -> OK barrier off
RELEASE         -> OK released         # 放行被暂停的发送循环
```

服务器主动通告:`PENDING`(接受 pending 数据连接)、`ATTACHED <id>`、`PAUSED <id> <written>`、`SETTLED <id> <outcome>`。

## 运行测试

```bash
npm test        # 或 node --test test/
```

测试以子进程启动真实服务器,使用真实的控制/数据双 TCP 连接,覆盖:慢读(屏障堵住数据连接)期间 ABOR 生效、零字节断点(`REST` 到文件末尾)、末尾完成竞争(末字节已冲刷 vs `ABOR`,只允许一种结论)、旧监听器迟到的连接不被新传输使用、`REST` 消费规则、`425`/`426`/`450`/`225` 时序、CRLF 分片解析等。每个用例末尾都有"静默期"断言,确保旧传输的回调不会再产生任何多余控制应答。
